# 常见错误

## 适用对象

启动应用、配置模型或导入资料时遇到问题的用户。

## 前置条件

先记录页面提示的原文，并确认当前操作属于模型、知识、Skills 还是 MCP。

## 操作步骤

### 依赖安装失败

确认已在项目根目录执行 `uv sync`。如果要重新验证项目，可运行 `uv run pytest`；不要把 `.data` 或 API Key 提交到 Git。

### 模型无法回答

检查设置中的模型是否存在并启用；重新确认服务商配置、API Key 和网络，再编辑模型并重试。

### 知识库没有结果

确认文档已经出现在知识列表中，再使用文档中确实存在的关键词搜索。当前支持文本、代码、PDF 和 DOCX。

### Skill 没有生效

检查 Skill 是否启用，并在消息中明确写出 Skill 名称。内置 Skill 可以查看，但不能直接编辑。

### MCP 启动失败

进入 MCP 的“运行环境”查看缺少的组件，点击安装必需环境；回到服务器页面后刷新并点击“测试连接”。

<InfoBox tone="note" title="先看真实状态">

MCP 添加成功的前提是真实握手和工具列表读取成功；不要只根据配置文件存在就判断服务可用。

</InfoBox>

## 预期结果

对应能力恢复可用，或你已经得到一条明确的失败原因，便于继续处理。

## 常见问题

如果仍然失败，保留完整错误信息，并区分是本地依赖、模型服务商、文件格式还是 MCP 服务器问题。
